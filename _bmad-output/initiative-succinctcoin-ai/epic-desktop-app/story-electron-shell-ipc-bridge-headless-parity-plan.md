# Story 6.2 — App: Electron shell + preload/IPC bridge (AD-11) + core-suite headless parity

## Goal

Scaffold the NEW `packages/app` pnpm workspace package (the `packages/*` glob picks it up) and build the Electron shell's MAIN half: the main process hosts the core (a REAL `createCore` with real ports + a REAL identity, per AD-11 the keys live in main), a preload `contextBridge` exposes the commands + the event stream + the read-API to the renderer with **NO key material** (the AD-11 renderer/IPC half — the spine: "the renderer/IPC half (the electron preload bridge) is epic 6's job — 6.2/6.3"), and the core suite passes UNCHANGED under plain-Node (CAP-6 — the root `test`/`typecheck`/`build` STAY core-scoped, so parity holds by construction; the app package-local suite ALSO runs under plain-Node). The React renderer is 6.3; the electron-forge packaging + closing e2e is 6.4.

## The monorepo wiring (the new `packages/app`)

- `packages/app/package.json`: `name: "@succinctcoin/app"`, `version: "0.0.0"`, `private: true`, `type: module`. `dependencies: { "@succinctcoin/core": "workspace:*" }` (the workspace link — the app imports the core as a PACKAGE, AD-1). `devDependencies`: `electron: 44.5.1` (the pinned app spine; provides the `electron` TYPES — `electron.d.ts` — for the main/preload typecheck), `typescript: 5.9.2`, `vitest: 5.0.3`, `@types/node: 24.9.2`. NO `react`/`vite`/`@electron-forge/cli` yet (those are 6.3/6.4).
- `packages/app/tsconfig.json`: mirror the core's — `target`/`module` ES2022 + NodeNext, `strict`, `moduleResolution: "NodeNext"`, `outDir: "dist"`, `rootDir: "src"`, `declaration: true`, `skipLibCheck`. No `paths` — `@succinctcoin/core` resolves via the pnpm workspace symlink → `packages/core` (its `package.json` `main: ./dist/index.js` / `types: ./dist/index.d.ts`).
- **Build order (CRITICAL):** the app imports `@succinctcoin/core` → its `dist` (compiled JS + `.d.ts`). So a CORE build (the root `build`) is a PREREQUISITE for the app's typecheck/test/build. The gate sequence builds core first, then app.
- **Electron binary:** install electron with `ELECTRON_SKIP_BINARY_DOWNLOAD=1` — the ~100 MB binary is only needed to LAUNCH the app (6.4's packaged e2e); 6.2's typecheck + headless test need only the `electron` TYPES (present in the npm package without the binary) + the PURE core-host (which imports no electron). This keeps the sandbox install light + the 6.2 test headless-safe (no Electron launch).

## The design (4 modules — the AD-1 seam applied to the app)

The electron-specific glue (BrowserWindow, ipcMain, contextBridge) is kept THIN; the core-hosting LOGIC is a PURE module (no electron import) so the in-app path is testable under plain-Node (the AD-10 electron-main test target, headless-safe).

1. **`packages/app/src/main/core-host.ts`** (PURE — NO electron import): `createCoreHost(opts): CoreHost`. `opts` = `{ net: NetPort, store: StorePort, gate: GateVerifier, forwardEvent: (event: CoreEventName, payload: CoreEventPayload) => void, identity?: IdentityKeypair }`. The host builds a CHAIN-TIME `ClockPort` internally (AD-3 — the `ClockPort` is `slotIndex()`/`lastBlockHash()`; the node-loop reads chain-time from the STORE, so the clock is used only for the `CoreStarted`/`CoreStopped` `slot` field. It is a cache the host updates from the event stream: the genesis is committed at boot via `mineAndApply` and emits NO `BlockApplied`, so the cache starts at -1 and `CoreStarted` carries that; the first `BlockApplied` (the loop's first mined block) advances the cache). It calls `createCore({ net, store, clock, gate, uiSink: { sink: (e, p) => forwardEvent(e, p) }, identity })` and returns the `CoreHost`: `{ start, stop, startMining, getChainHead, getBalances, getPeers, getBlock }` (delegating to the `CoreInstance`'s commands + read-API). **AD-11:** the `forwardEvent` callback carries ONLY the core's event payloads (already key-free — `BlockApplied`/`CoreStarted`/`CoreStopped` carry no keys, 6.1) + the read-API returns key-free read-models (`ReadChainHead`/`ReadBalances`/`ReadPeer`/`ReadBlock`). The `identity` keypair (if provided) is passed to `createCore` and NEVER surfaced — the host creates/holds it; the `CoreHost` surface never exposes `.secret`.

2. **`packages/app/src/main/ipc-channels.ts`** (PURE — NO electron import): the IPC channel names + the routing tables. `IPC_COMMANDS` = the command names (`"core.start"`, `"core.stop"`, `"core.startMining"`) mapping to `CoreHost` methods; `IPC_EVENTS` = the core event names (`"coreStarted"`, `"blockApplied"`, `"coreStopped"`) mapping to the webContents channel; `IPC_READ` = the read-API names (`"chainHead"`, `"balances"`, `"peers"`, "block"`) mapping to `CoreHost` read methods. This is the ONE owner of the IPC shape (the main + preload + the test all reference it — no duplicated string literals).

3. **`packages/app/src/main/index.ts`** (electron — THIN glue): imports `electron` (`app`, `BrowserWindow`, `ipcMain`) + the core-host + the ipc-channels. On `app.whenReady()`: build the REAL ports (the memory `createNetAdapter` for the testnet [the real net transport is a config choice — memory is the AD-10/AD-1 testnet default], a `FileChainStore` under the app's userData dir, `createOfflineGateVerifier({ acceptedGates })`, a REAL identity via `deriveIdentityKeypair(seed)` where the seed is a fixed per-install value [the key material lives in MAIN — AD-11]), create the `CoreHost` (its `forwardEvent` = `webContents.send(channel, payload)`), register the `ipcMain.handle` handlers (commands + read-API), create the `BrowserWindow` (loads the renderer — a placeholder `index.html` in 6.2; the React renderer is 6.3), and wire `ipcMain` for the event stream. **The electron-specific surface is thin; the core-hosting is delegated to the pure `createCoreHost`.**

4. **`packages/app/src/preload.ts`** (electron — THIN glue): imports `electron` (`contextBridge`, `ipcRenderer`) + the ipc-channels. `contextBridge.exposeInMainWorld("succinctcoin", { start, stop, startMining, getChainHead, getBalances, getPeers, getBlock, on(event, cb) })` — each command/read-API is an `ipcRenderer.invoke(channel)`; `on(event, cb)` subscribes via `ipcRenderer.on(channel, (_, payload) => cb(payload))`. **NO key material is exposed** (AD-11 — the bridge surface is commands + the event stream + the read-API only). A `src/preload.d.ts` (or the renderer's global declaration) types `window.succinctcoin`.

A static guard pins this (the host + the bridge surface expose no key names).

## The test (`packages/app/test/core-host.test.ts` — the AD-10 electron-main target, headless-safe)

Imports `createCoreHost` (+ the REAL core ports: `createNetAdapter`, `FileChainStore`, `createOfflineGateVerifier`, `deriveIdentityKeypair`) from `@succinctcoin/core` + the app's `src/main/core-host.ts` + `src/main/ipc-channels.ts` (NO electron import). A `forwardEvent` recorder (an in-memory list). Rows:

1. **the in-app path mines + forwards (AC1):** `createCoreHost` (memory net, FileChainStore in tmp, offline gate, a real identity) → `start()` (mines the genesis block, emits `CoreStarted`) → `startMining()` (starts the integrated slot loop) → bounded-poll `forwardEvents` for a `BlockApplied` past the genesis slot → assert the events are `CoreStarted` (first) then `BlockApplied` (the loop mined) + the `getChainHead()` slot advanced past genesis. `stop()` in `afterEach`.
2. **AD-11 — no keys cross the boundary (AC2):** after a `BlockApplied`, assert NONE of the `forwardEvent` payloads (JSON-scanned) contain a key-material name (`privateKey`/`secret`/`keypair`) + NONE of the read-API results (`getChainHead`/`getBalances`/`getPeers`/`getBlock`) do. The identity's `identityId` (the peer ID) MAY appear (it's public, AD-11: "the UI gets only peer IDs, status, signed artifacts") — but the `.secret`/private key never does.
3. **the read-API reflects the mined state (AC1/AC3):** `getBalances()` returns the `MINT_ID` balance (the emission) + `getChainHead()` returns the mined head (slot/hash). The in-app data source (the read-API) is real.
