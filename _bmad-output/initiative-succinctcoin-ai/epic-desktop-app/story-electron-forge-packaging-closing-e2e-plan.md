# Story 6.4 — electron-forge packaging + the closing end-to-end suite (full Done-when)

## 1. Intent

The LAST story of the initiative. It has two parts (the ticket is NOT test-only — it adds the forge config + the e2e):

1. **electron-forge packaging** — wire `@electron-forge/cli` 8.0.1 so `packages/app` packages into a runnable desktop app (the spine pin). The forge config + the app's entry (`main`) make the app packageable; the e2e proves the config RESOLVES + the entry is the electron main process.
2. **the closing e2e suite** — the 3.9 / 4.10 / 5.10 precedent (one integrated run proving ALL FIVE epic Done-when), but this one COMPOSES the app's built modules (the core host, the renderer's ui-state) over `@libp2p/memory` (zero real sockets, AD-10).

It COMPOSES the built seams (the core node loop, the shell's pure core host, the IPC bridge shape, the renderer's ui-state) imported from their packages — never re-implementing any of them (AD-1 / AD-2 / AD-7).

## 2. The key build decision (settled at start, per the ticket's `unknown`)

**The e2e drives the MAIN-PROCESS code path directly under vitest via the `@libp2p/memory` electron-main target — it does NOT spawn a real (headless) electron process.**

Rationale (recorded here so the decision is visible):

- The spine's AD-10 rule is *memory transport, zero real sockets in CI*. A real electron spawn adds a real GUI process (flaky headless — the ticket itself notes "a full electron spawn may be flaky headless"). The electron binary is NOT installed (6.1/6.2/6.3 all installed with `ELECTRON_SKIP_BINARY_DOWNLOAD=1`); installing it is a large download + a headless GUI process is the flake vector.
- The in-app path is already PURE + headless-testable: `src/main/core-host.ts` has NO electron import (AD-1) — 6.2's `core-host.test.ts` proves the main-process core (real ports over `@libp2p/memory`) mines + forwards `BlockApplied` under plain Node. `src/renderer/ui-state.ts` is PURE (no DOM/electron) — 6.3's `renderer.test.ts` proves the reducer + snapshot under plain Node. The 6.4 e2e INTEGRATES the two (the host's `forwardEvent` → the renderer's ui-state reducer) — that integration is the NEW proof.
- The "packaged app" half is proven by the FORGE CONFIG RESOLVING (a test asserts the config is valid + the app's entry is the electron main process) — NOT by actually running `electron-forge package` (which would download electron + launch the GUI — flaky). The forge config makes the app packageable; the e2e proves the config + the in-app path.
- This is consistent with the 3.9 / 4.10 / 5.10 precedent (the closing e2e is a headless, memory-transport, no-real-sockets suite).

The "packaged app on a testnet shows blocks mined" Done-when is therefore satisfied as: *the app is packageable (the forge config resolves + the entry is the electron main process)* AND *the main-process code path the packaged app would run mines blocks over `@libp2p/memory` + the `BlockApplied` reaches the renderer's data source* (the e2e).

### 3.4 Carried items — disposition (recorded, NOT silently dropped)

The 6.2/6.3 deferrals that named 6.4 as their home. Disposition for THIS story (the ticket's `verify` is the contract; none of these is in it):

- **F2 snapshot race (6.3 deferral — "add a sequence guard if the e2e proves flaky")**: the e2e drives the host + the reducer directly (no concurrent snapshot calls — the reducer is fed the recorded events synchronously). The snapshot race only arises in the LIVE hook (the browser). If the e2e is flaky, a sequence guard is added to `useSuccinctcoin.ts`; otherwise DEFERRED (benign — each snapshot reads the current read-API state; the next event self-corrects).
- **6.2 F2 genesis-path fix ("thread the app's `genesisPath()` into `host.start()`")**: DEFERRED. It is a latent-defect fix for a *packaged/relocated layout* (the app's `genesisPath()` + the core's `defaultGenesisPath()` independently resolve to the repo-root `config/genesis.json` today). The 6.4 e2e drives `createCoreHost` directly (it does NOT exercise the thin electron glue `src/main/index.ts` where the fix would land), so an untested change to the glue is out of scope here. Recorded in `deferred-work.md`.
- **Per-install random identity seed**: DEFERRED. The 6.2 `IDENTITY_SEED` is a fixed 32-byte constant (the key lives in main, AD-11). A per-install seed (a `node:crypto` `randomBytes(32)` persisted to `userData`) is a real feature (randomness + persistence) NOT in the 6.4 `verify`. Recorded in `deferred-work.md`.
- **Real net transport config choice**: DEFERRED. `@libp2p/memory` is the testnet default (AD-10). The real net transport (tcp+noise+yamux) is a production deployment concern, NOT in the 6.4 `verify` (which is about the testnet + the headless parity). Recorded in `deferred-work.md`.

## 4. Never list (the spine rules this story must not break)

- **AD-1** — only the shell imports electron; the core has ZERO UI imports; the e2e + the ui-state import ONLY the app's PURE modules + the core's PUBLIC package surface (never core internals, never electron).
- **AD-2** — `applyBlock` is the single mutation path (the e2e composes it via the host, never re-implements it).
- **AD-3** — chain-time only (NO RNG / wall clock): the e2e wait is a BOUNDED poll (a `setTimeout` deadline + a tick loop — a liveness bound, NOT a timestamp read); the identity seed is a pinned 32-byte constant (no `Math.random`).
- **AD-9** — the UI is read-only via the read-API (the e2e drives the host's commands `start`/`startMining` — the e2e is the test driver; the RENDERER stays display-only; the ui-state is PURE).
- **AD-10** — `@libp2p/memory`, ZERO real sockets in CI (the e2e runs the in-app path over memory; NO electron spawn; NO real socket).
- **AD-11** — the identity keys live in the host (main); the renderer + the event payloads + the read-API carry ONLY peer IDs, status, signed artifacts (the e2e re-proves this over the integrated path).
- **CAP-6** — the core suite passes UNCHANGED under plain-Node (the core `src/` + `proto` + `package.json` are untouched by 6.4 — the diff scope gate).
- **`@libp2p/kad-dht` must NOT appear in any package.json** (the 5.8 decision); **big.js never outside the core ledger boundary** (the app imports NO big.js).
- **reject = a normal `false` / REJECT, never a throw** (the spine rule).
- **`dist/` is gitignored** (never committed).
