⚡ spark 01

Rendezvous convention

run libp2p's existing /rendezvous protocol on volunteer nodes with namespace = genesis hash; a built-in capability nobody has armed yet

⚡ spark 02

Installer-fresh hints

each release binary embeds a peer snapshot from build time, explicitly stamped stale-by-design - a hint born expired, never a root

⚡ spark 03

Self-healing logs

on boot the node re-parses its own old connection logs to rediscover past peers after a network change - your history is your private seed list

⚡ spark 04

Rollback-safe books

because announcements are block data, a reorg rolls back the address book consistently with the chain - no off-chain state to desync

⚡ spark 05

Reachability-class intros

introductions carry how-to-reach (direct/relay/via-LAN); NATed nodes get relay-address intros so introductions actually connect

⚡ spark 06

Reciprocity meter

nodes track introductions given vs taken and throttle pure free-riders locally - tit-for-tat keeps seeding generous without token incentives

⚡ spark 07

ChainId in every record

peer records are network-scoped by chain id so testnet peers can never contaminate mainnet books

⚡ spark 08

Docs-as-dialtone

the project README itself, mirrored everywhere, carries a signed peers block at its foot - documentation is infrastructure

⚡ spark 09

Acoustic out-of-band

ultrasonic handshakes between nearby devices (chi.mp3 style) for air-gapped rooms - kept as the whimsy tier of redundancy

⚡ spark 10

Municipal fiber peering

cities running public wifi could run an entry node like they run NTP mirrors - aiming adoption, not protocol: discovery as civic utility
