- (decision) Paradigm: event-driven hexagonal core — packages/core is a pure-Node event-emitting state machine (ports: net, store, clock=chain-time, gate, ui-sink; adapters: libp2p, file store, chain slot, gate-credential-verifier, IPC bridge); shell is a thin adapter client. Chosen over layered-monolith because the core must run in 3 hosts (plain Node CI, Electron main, future daemon) with one code path.
- (decision) AD-1 core/shell seam [ADOPTED from spec constraint 6]: packages/core has zero imports of electron/renderer/UI; shell imports core, never reverse; core exposes events (out) + commands (in). Binds all units. Prevents core acquiring host dependencies and the test suite fragmenting.
- (decision) AD-2 single mutation path: all chain+ledger state mutation goes through one applyBlock(block) function invoked only by the consensus loop; ledger and chainstore are read-only everywhere else (including UI). Prevents two builders crediting balances via different paths (UI optimistic credit vs net-apply vs consensus-apply) — the classic ledger-divergence bug.
- (decision) AD-3 chain-time only: every protocol decision (window index, lookback L, ticket validity, draw, difficulty) uses chain time (slot count + last block hash), never wall clock; wall clock allowed only for UI display. Prevents clock-dispute ticket invalidation (attack-pass A-3) and nondeterministic tests.
- (decision) AD-4 identity is protocol, gate is external: the protocol verifies gate credentials OFFLINE (signature/credential check only) — the gate is never a per-window network dependency; gate outputs are opaque credentials against a registered verifier interface; new gates enter only by protocol upgrade (dual gate at launch). Prevents gate SPOF on the hot path and two builders trusting gate outputs at different levels.
- (decision) AD-5 money types: amounts are integer base units (BigInt) in memory and on wire; big.js appears only at two boundaries (fee = amount x rate at block apply; display conversion); floats are banned from the ledger; wire/JSON encoding = decimal string (Big.toJSON), never binary float, never raw BigInt (JSON.stringify(123n) throws). Prevents float drift and serialization divergence between two units.
- (decision) AD-6 hot-path crypto: per-attempt PoW = node:crypto sha256 + plain integer counter; big.js and pure-JS keccak are banned from per-attempt code (measured 1000x / 35x penalties). Prevents a builder 'helpfully' using big.js or a uniform hash lib in the mining loop.
- (decision) AD-7 verifiable draw is a pure function: election = f(valid tickets, per-window challenge, uptime weights) with no RNG source other than committed nonces and no network-position term; any node can recompute the winner; a block whose (ticket, nonce) does not verify the draw is rejected. Prevents broadcast-race degeneracy (attack-pass RT-2).
- (decision) AD-8 wire format: protocol messages via protobuf (protons-runtime, libp2p ecosystem convention); amounts as decimal strings; IDs as 32-byte hex; one stable topic per message class (blocks, tx, tickets, gossip). Prevents two units choosing incompatible encodings (uint64 overflow vs decimal string) or ad-hoc JSON on hot topics.
- (decision) AD-9 single writer persistence: chainstore is the only owner of on-disk state; exactly one writer (the consensus loop in the main process); UI and net read via the core read API, never the store directly; store engine (SQLite/LevelDB/custom) is a code-level choice. Prevents two-process write corruption and UI bypassing validation.
- (decision) AD-10 testability seam [ADOPTED from spec CAP-6]: all core tests run plain-Node with @libp2p/memory; zero real sockets in CI; the libp2p electron-main test target (verified present in @libp2p/memory 2.0.28 package.json) covers the in-app path. Prevents the test suite requiring a desktop shell or network.
- (decision) AD-11 key material boundary: identity private keys live in the core (Electron main process); they never cross the IPC boundary to the renderer in plaintext — the UI receives only peer IDs, status, and signed artifacts. Prevents renderer compromise exposing identity keys (the rental-prevention property).
