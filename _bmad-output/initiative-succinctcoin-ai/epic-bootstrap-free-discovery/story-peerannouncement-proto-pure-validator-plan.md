## Intent

**Problem:** CAP-7 discovery (epic 8) needs signed self-announcements — the record type whose signature IS the liveness proof — but the wire schema has no announcement message and core has no way to validate one. Tickets 8.3 (blocks carry announcements) and 8.4 (the address book) both consume this contract; without it they would each invent their own bytes.

**Approach:** Add `PeerAnnouncement` to `protocol.proto` (purely additive message, like epic 5's envelopes — no existing field touched), regenerate + commit the protons types (PROTO_OK), and add a NEW pure module `core/src/discovery/announcements.ts`: the AD-12 canonical digest over the announcement, Ed25519 sign/verify following the `identity.ts` conventions exactly, and a PURE validator returning `{ok:false, reason}` — never throwing on hostile input. No consensus, gossip, or boot wiring (that is 8.3's tracer).

Pinned decisions (the ticket defers these to build time):
- **Digest layout** (domain-separated, BE fixed-width per AD-12): `sha256( utf8("succinctcoin/PeerAnnouncement/v1\0") ‖ utf8(identityId) ‖ sha256(u32be(n) ‖ utf8(multiaddr) for each of the SORTED multiaddrs, concatenated) ‖ u256-observed-part ‖ u64be(slotStart) ‖ u64be(slotEnd) ‖ utf8(chainId) )` where the observed part is `0x00` when absent else `0x01 ‖ utf8(observedExternalAddr)`. Sorting (lexicographic, dedup-free — duplicates are a shape error instead) makes the digest order-canonical on the wire list. Pinned by golden vector (deterministic key from seed, like identity's).
- **Shape limits** (block-size budget defense): `multiaddrs` 1–8 entries, each `/`-prefixed (the genesis-bootstrap rule), no whitespace/control chars, ≤160 chars; `slotEnd >= slotStart`; signature exactly 64 bytes; identityId 64-lowercase-hex; chainId 1–64 printable ASCII.
- **Freshness**: validator takes a CALLER-SUPPLIED `currentSlot` (never `Date` — AD-3): reject `slotEnd < currentSlot` (expired) and `slotStart > currentSlot` (not-yet-valid). Chain match: `chainId === expectedChainId` (also caller-supplied).
- **chainId source**: genesis gains an OPTIONAL `chainId` string (default `"succinctcoin-v" + protocolVersion` when absent — existing fixtures stay green); 8.3's emitter signs with it, validators compare against it. The proto field itself is required-on-wire.

## Boundaries & Constraints

**Always:** validator is pure (no clock/net/fs; property-testable); verification reconstructs the public key from `identityId` alone (D2 pattern — SPKI prefix ‖ raw bytes); a malformed signature/identity never throws (reject with reason); generated proto types are the ONLY protocol type source (AD-12).

**Never:** no gossip topic, no node-loop/applyBlock wiring, no address book (8.3/8.4 own those); no changes to existing message field numbers/types; no `Date`/wall clock anywhere; renderer never sees key material (AD-11 — this module lives in core, takes keys as arguments).

## Implementation Notes

Built 2026-10-18. Deviations & discoveries, all deliberate:

- **`.secret` single-reader invariant forced a seam the Code Map didn't foresee**: "copy helpers locally" works for hashing but NOT for signing — `core-node-loop.test.ts` + `identity-key-surface.test.ts` pin `identity/identity.ts` as the ONLY module reading the keypair secret. Fix: `identity.ts` gained `signDigest(keypair, digest)` (the reader stays single), consumed via core-internal import; per review it is deliberately NOT exported from the package barrel (no arbitrary-digest signing oracle ships externally).
- **protons int64 = bigint**: decoded wire records carry bigint slots and the generated Input types require bigint — the fields/digest/validator accept `number | bigint` end-to-end (pinned by a decode→validate row: THE 8.3 path). The repo convention `Block.slot: bigint` confirmed this reading.
- **Digest reading pinned** (review round): the frozen `u256-observed-part` is implemented as exactly 32 bytes — `sha256(0x00)` absent / `sha256(0x01 ‖ utf8(addr))` present; the multiaddr part's `u32be(n)` is each entry's BYTE LENGTH (length-prefixed concatenation over the SORTED list, then sha256). Only `undefined` means absent — an empty-string observed addr binds as present and fails shape (row-pinned).
- Genesis `chainId`: required on the TYPED interface (default always filled by `validateGenesis`), optional in the RAW JSON — typed-optional would push undefined-handling onto every consumer for no benefit; no literal-construction caller exists (`net-config` uses `Pick`).
- `AnnouncementContext.currentSlot` non-integer THROWS by design (caller precondition, node-loop slots are integers) — record-level junk never throws.
- Golden vectors re-pinned after the observed-part fix: digest `5c7e132c…f56663`, signature `1638e77b…e31a01` (seed `(0xa1+i)%256`).
