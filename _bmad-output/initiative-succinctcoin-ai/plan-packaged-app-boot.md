## Intent

**Problem:** `electron-forge package` produces an app that cannot boot as a working product. THREE blockers: (1) `index.ts` `genesisPath()` resolves the repo-root `config/genesis.json` (4 levels up from `dist/main/`), which is NOT in the package, and the core resolves its own copy independently (6.2 F2); (2) the package cannot resolve `@succinctcoin/core` at all — under pnpm's strict layout it is a `workspace:*` symlink and the transitive libp2p graph is not in `packages/core/node_modules`, so no copy of the app dir can resolve it (6.4 blocker b); (3) the preload is ESM but is emitted as `dist/preload.js` — Electron ≥ v28 (pin 44.5.1) parses preload scripts as CJS REGARDLESS of the package's `"type": "module"` (official ESM docs: "Preload scripts will ignore `type: module` fields, so you must use the `.mjs` file extension in your ESM preload scripts"; the support-matrix row for unsandboxed + context-isolated renderers — exactly this app's config — repeats the rule) — so the ESM-syntax `dist/preload.js` is a SyntaxError: `contextBridge.exposeInMainWorld` never runs, `window.succinctcoin` is undefined, and the renderer's entire data source (the 6.3 hook) is dead while the main process boots and mines (iteration-1 review F1, verified against the Electron docs + the on-disk v1 bundle).

**Approach:** make the app self-contained AND actually bootable: the app build copies the repo genesis into `dist/config/genesis.json` (the ONE source the gate registry AND `host.start(genesisPath())` read), the main+preload processes are built with the app's EXISTING Vite (node/ssr builds, `electron` external, the core INLINED), and the preload is emitted as `dist/preload.mjs` (the Electron ESM-preload rule) and loaded via `new URL('../preload.mjs', import.meta.url)` — the packaged app needs no workspace node_modules and its bridge actually works.

## Boundaries & Constraints

**Always:** one genesis source (bundled `dist/config/genesis.json`, byte-identical copy of repo `config/genesis.json`); every `host.start` call passes the app's `genesisPath()` (never the core's independent default); electron imports stay ONLY in `src/main/index.ts` + `src/preload.ts` (AD-1); bundle externals ⊆ {`electron`, node builtins — with or without the `node:` prefix; Node's ESM loader resolves both identically}; AD-10 (tests: plain Node, no electron spawn, no DOM); emit layout `dist/main/index.js` + `dist/preload.mjs` + `dist/renderer/` — the preload MUST be `.mjs` (the Electron ESM-preload rule; a `.js` ESM preload never loads); the app build CLEANS stale emits from prior pipelines first (an unclean rebuild never ships them); the app test suite is SELF-SUFFICIENT on a fresh checkout (a row that needs a build artifact produces it); the in-app messages name commands that actually work; the core package is UNTOUCHED.

**Never:** no new dependencies (lockfile unchanged); no bundler beyond the pinned vite 8.3.2; no changes to core `src/`/`proto`/`package.json`; no `@libp2p/kad-dht`; no changes to the renderer vite build or the forge config shape (the 6.4 `E2E_FORGE_CONFIG_RESOLVES` row pins it); no node_modules vendor/copy into the package.

## Implementation Notes (v1 — superseded by the iteration-1 loopback; observations to re-verify, not to trust)

- **Two Vite configs (the plan's implementer's choice):** `vite.main.config.ts` + `vite.preload.config.ts` (one per entry), rather than one multi-entry config — the pinned emit LAYOUT (`dist/main/index.js` + `dist/preload.js` at two different depths) maps 1:1 onto two single-entry SSR builds; a multi-input config names outputs by entry key and would not produce the layout without further `entryFileNames` machinery. Both are node/ssr builds: `build.ssr: '<entry>'`, `ssr.target: 'node'`, `ssr.external: ['electron']`, `ssr.noExternal: true` (inline the WHOLE core graph), `emptyOutDir: false` (the shared `dist/` is never wiped; the renderer build's `emptyOutDir: true` empties only `dist/renderer/`).
- **Build order (the `build` script):** `tsc -p tsconfig.build.json` (now typecheck-only, `noEmit: true`) → `vite build` (renderer, UNCHANGED config — its bundle came out byte-for-byte the same asset, 222.62 kB `index-gGur1doq.js`) → `vite build -c vite.main.config.ts` → `vite build -c vite.preload.config.ts` → `node scripts/copy-genesis.mjs` (last — the bundled genesis lands with the final dist state).
- **Bundle shape (observed):** `dist/main/index.js` = 1,597.65 kB (518 modules inlined — the core + the whole libp2p graph + big.js), single file (no code-split chunks), `import.meta.url` left native (6 occurrences — the entry's `../preload.js` / `../renderer/index.html` / `../config/genesis.json` relative loads work in dev AND in the asar). `dist/preload.js` = 1.74 kB (the pure IPC tables inlined; the core's types are `import type`, erased).
- **Deviation (recorded, no behavior change): bare node-builtin specifiers in the bundle.** Third-party code in the inlined graph writes some builtin imports WITHOUT the `node:` prefix (`crypto`, `os`, `path`, `net`, `dns/promises`); the rest are prefixed (`node:fs`, `node:crypto`, ...). The frozen boundary is "bundle externals ⊆ { `electron`, node builtins }" — satisfied. The I/O matrix's literal `node:*` projection is normalized in the `BUNDLE_SELF_CONTAINED` row: every extracted import specifier (static `from '...'` + dynamic `import('...')`) must be `electron` or a member of `node:module`'s authoritative `builtinModules` set (prefix optional) — the Electron main process's Node ESM loader resolves the bare forms identically.
- **Surprise (scan design): inlined code QUOTES package-like names.** The rolldown output carries `//#region .../@libp2p/.../...` source markers (some wrap to a second line) and the inlined `@libp2p/interface` defines well-known symbols as `Symbol.for("@libp2p/connection")`-style strings. A whole-text `['"]@libp2p/` scan false-positives on them — they are inlined code, not imports. The `@succinctcoin/core` / `@libp2p/*` / `big.js` negative checks therefore run on the EXTRACTED import-specifier set (which is also exactly the plan's "import specifiers ⊆ ..." subject); the positive electron-or-builtin check already excludes any npm specifier.
- **The inlined core's `defaultGenesisPath()` is inert in the bundle.** Inside `dist/main/index.js` the core's three-levels-up default would resolve to `packages/config/genesis.json` (nonexistent) — harmless because EVERY `host.start` call threads the app's bundled `genesisPath()` (the core is UNTOUCHED; its default still serves the repo-checkout harnesses, per the Design Notes).
- **Root-suite count (the 6.2/6.3/6.4 workspace-glob precedent):** 273/273 (42 files) = the 268 prior + the 5 new rows (1 new file); the core package-local 256/256 (38 files) is UNCHANGED (CAP-6's intent holds — the diff-scope gate proves every core file untouched).

## Design Notes

**Bundle, not vendor-copy.** The tempting fix — copying the core (and its deps) into the app dir so the package resolves `@succinctcoin/core` — fails under pnpm's strict layout: the core's transitive libp2p graph lives in the root `.pnpm` store, NOT in `packages/core/node_modules` (all core deps are `devDependencies`), so a copied app dir can never resolve it; a `pnpm deploy` step would add tooling the spine bans ("no second toolchain"). Vite is ALREADY the app's toolchain (the renderer): a node/ssr lib build of main+preload inlines the core + its whole graph, externals stay {`electron`, node builtins}, and the packaged app ships `dist/` only — smaller and immune to the pnpm symlink layout.

**The preload must be `.mjs` (the third boot blocker).** Electron's ESM support matrix (official docs, feature since v28; pin 44.5.1): for unsandboxed + context-isolated renderers — exactly this app's `contextIsolation: true`, `sandbox: false` config (the AD-11 boundary) — "ESM Preload Scripts must have the .mjs extension", because preload scripts IGNORE the package's `"type": "module"` field. The repo is all-ESM (`module: NodeNext`, `"type": "module"`), so the preload SOURCE is ESM and the 6.2 tsc emit was ESM-in-`.js` — a latent SyntaxError at packaged boot (in dev the same defect existed; it only bites in the package's module context). The alternative — emitting the preload as CJS — would require a second module mode for one file (transpiler CJS transform or a `.cjs` hand-maintained duplicate) against the spine's "no second toolchain" and the repo's uniform ESM; renaming the emit to `dist/preload.mjs` (one `entryFileNames` setting + one `new URL` path) is the smallest change. The docs' other ESM-preload caveats are satisfied: dynamic `import()` in the preload needs context isolation (ON), and the "runs after page load on empty pages" caveat does not apply (the renderer page has content).

**`import.meta.url` survives.** The main process locates the preload, the renderer and (now) the genesis relative to its own module URL. Vite's node/ssr build leaves `import.meta.url` native, so the relative layout (`../preload.js`, `../renderer/index.html`, `../config/genesis.json` from `dist/main/`) works in dev AND inside the asar unchanged.

**Bare `host.start()` in the 6.2/6.4 tests stays.** Those harnesses drive `createCoreHost` from the repo checkout — the core's `defaultGenesisPath()` (repo root) still resolves, and the core is untouched; this story only changes the THIN glue (`index.ts`), which no test imports.

**Residual (same disposition as 6.4 F2):** actually running `electron-forge package` + launching the `.app` is not executable here (the electron binary is install-skipped); the gates prove the package's module graph is self-contained (the scan) and the boot inputs are real (the bundled-genesis rows). The two former boot blockers are both closed.
