# D1 (deep dive) — Equal-chance-per-node consensus for a JS cryptocurrency — Round 1

Researcher: D1 dimension. Accessed: 2026-09-29. Budget: 8 sources read / ~15 calls — spent ~7 reads, 6 fetch calls.

## What I looked for and could not find

- **"Proof of Spacing" as a named mechanism** — zero search results for that exact name. The nearest real families are proof-of-space / proof-of-spacetime (Chia, Filecoin). If the brief's author meant something specific, the name may be a conflation; flagged for the lead.
- **Golem's Proof-of-Eligibility (PoE) primary spec** — the brief names Golem PoE, but current Golem docs (docs.golem.network, 2026) describe an Ethereum-based network (GLM ERC-20 on Ethereum mainnet + Polygon L2) with no PoE lottery. Golem's pre-2021 whitepaper/GitHub (golemfactory) is the place to chase; I did not retrieve it this run.
- **A deployed coin that actually guarantees "equal chance per running node"** (probability ≈ f(uptime), not f(stake) or f(capacity)). I found none. Every major live system weights by stake (Algorand), capacity (Bitcoin-like), or storage (Chia). This absence is itself the headline finding: the exact property in the brief is not implemented by any system I could evidence; the closest deployable pattern is a VRF lottery *re-weighted per registered node*, for which no major production deployment was found.
- **IOTA's Tangle** (named in brief) — not retrieved this run.
- **2024–2026 deployed coins using low-difficulty equal-node PoW** — none found; only a 2026 research proposal (Proof of Commitment, arXiv 2601.04813).

## Findings (claims)

ref=[D1.1] status=unverified class=mechanism pub=2026-01 — Permissionless consensus requires a scarce resource for leader election + Sybil resistance; PoW/PoS instantiate it via *parallelizable* resources (computation, capital), which "can be subdivided across many identities at negligible marginal cost, making linear Sybil cost fundamentally unattainable." This is the formal statement of the core tension: any parallelizable resource gives an operator N identities → N× odds. Source: https://arxiv.org/abs/2601.04813. Publisher: arXiv (Maleki, Sainz, Legarda). Accessed: 2026-09-29.

ref=[D1.2] status=unverified class=mechanism pub=2025-01 — Slow/low-difficulty PoW (few-hashes-per-slot, "one CPU does one hash per slot"): a block is valid if its header hash is below a target set so one commodity CPU is expected to find ~one candidate per slot. What "equal" it actually guarantees: nothing node-equal — odds remain f(hashrate); it only removes ASIC advantage if the PoW function resists specialized hardware. Known attacks: hashrate-Sybil (N CPUs → N× odds), selfish mining, 51%-by-compute. The *verifiable* sequential-work variants (PoSW/iPoSW/VDF) are a heavy cryptographic research area (random-oracle constructions, incremental graphs), which is evidence that the "verifiable time" layer is where complexity lives, not the hash check itself. Source: https://www.mdpi.com/1099-4300/28/1/33. Publisher: MDPI Entropy (survey on Proof of Sequential Work). Accessed: 2026-09-29.

ref=[D1.3] status=verified class=mechanism pub=2017-05 — VRF/lottery slot assignment (Algorand "cryptographic sortition"): a user is the round-r potential leader iff `.H(SIG_i(r,1,Q_{r-1})) ≤ p`, where Q is a non-manipulatable seed; the user privately knows they were chosen and proves it with the signature credential. Two sources agree on the mechanism: (1) the primary paper (arXiv 1607.01341, Chen & Micali) and (2) the Algorand Foundation's own explainer (VRF = "a private lottery: participants privately know when they're selected, and everyone else can verify"). What it guarantees AS BUILT: in the money-weighted embodiment, a key holding a_i is selected with probability `p · a_i / M` (stake-weighted, not node-equal); in the user-weighted embodiment it is per-key, but the paper's own "Honest Majority of Money" implementation forces rich participants into multiple keys/copies (i,v) — i.e., it documents multi-homing as the way wealth converts into selection probability. Known attacks addressed in-paper: seed manipulation (look-back parameter k, k=40–70), pre-targeting of the leader (secret credentials + ephemeral one-use keys destroyed after use). Source: https://arxiv.org/abs/1607.01341 + https://x.com/AlgoFoundation/status/2104613154865168858 (full text read at https://readwhitepaper.com/algorand/). Publisher: arXiv / Algorand Foundation. Accessed: 2026-09-29.

ref=[D1.4] status=verified class=mechanism pub=2014-10 — Proof-of-Activity (PoA) hybrid: the PoW miner proposes the block, then a PoS-selected committee votes to finalize; the block reward is split (e.g., 90/10 or 80/20) between the PoW miner and the PoS validators. Two independent sources agree: (1) the primary paper (Dougherty, "Proof of Activity: Extending Bitcoin's Proof of Work via Proof of Stake," ACM 2014) and (2) crypto.com's glossary (independent publisher, same mechanism description). What it guarantees: the PoS portion is stake-weighted and the PoW portion capacity-weighted — neither portion is node-equal; a node-equal PoS portion would require re-weighting by registered identity, which no published PoA variant I read does. Source: https://dl.acm.org/doi/10.1145/2695533.2695545 + https://crypto.com/en/glossary/proof-of-activity-poa. Publisher: ACM / crypto.com. Accessed: 2026-09-29.

ref=[D1.5] status=unverified class=failure pub=2026-02 — Proof-of-time / VDF fragility: the IACR survey (last rev 2026-02-11) records that Ethereum abandoned its plan to replace RANDAO with a VDF after a discovered attack on the Minroot VDF, per Vitalik Buterin's blog of 29 Oct 2025 and a cryptanalysis ACM paper cited by the survey. This is the concrete "what broke" evidence for the proof-of-time family: a leading production project withdrew from VDF-based randomness. (Single source read this run; the Vitalik blog + ACM cryptanalysis are the two independent sources to double up in round 2.) Source: https://eprint.iacr.org/2025/637. Publisher: IACR ePrint (Arafat, "A Study of Blockchain Consensus Protocols"). Accessed: 2026-09-29.

ref=[D1.6] status=unverified class=failure pub=2026-04 — Proof-of-space (Chia) "equal per unit of stored space" broke in practice: in PoS1, attackers (Mad Max, Dr. Plotter) achieved ~50% plot-size compression, i.e., they proved more space than they stored by trading compute for storage — directly violating the space=cost assumption. Grinding (GPU plot generation on challenge) is the second attack. PoS2 (CHIP-48/49, hard fork scheduled Nov 2026, ~256-day phase-out) adds a chaining filter: honest farmer ~60k hashes/challenge vs ~536M hashes for a 1-bit-drop attacker (~8,000×). Odds remain f(storage), so multi-disk Sybil is linear in disk count. Single source (project's own Q&A); independent second source = the researchers' compression papers (lead for round 2). Source: https://www.chia.net/2026/04/30/proof-of-space-2-0-community-qa-summary/. Publisher: Chia Network. Accessed: 2026-09-29.

ref=[D1.7] status=unverified class=mechanism pub=2026-01 — 2026 research proposal directly targeting the brief's property: Proof of Commitment (PoCmt) grounds leader election in a *non-parallelizable* resource — sustained real-time human engagement — enforced by a Human Challenge Oracle issuing identity-bound, time-sensitive challenges; a cost-theoretic separation shows parallelizable-resource protocols admit ~zero marginal Sybil cost while PoCmt enforces a linear cost profile, with "commitment-proportional fairness" under partial synchrony. This is the only 2024–2026 source I found that explicitly aims at probability ≈ f(uptime/commitment) rather than f(capacity). Research stage, not deployed. Source: https://arxiv.org/abs/2601.04813. Publisher: arXiv (Maleki et al.). Accessed: 2026-09-29.

ref=[D1.8] status=unverified class=failure pub=2013-11 — Second-order attack (selfish mining): colluding miners can obtain more revenue than their fair share while remaining a minority — profitable from ~25% hash power under the paper's relay assumptions — and rational miners then join the colluding group until it becomes a majority. For equal-node designs the attack is qualitatively the same but the cost axis flips: an attacker needs 25–50% of *registered node identities*, so the attack cost is the Sybil/registration cost per node, not hashrate. Source: https://arxiv.org/abs/1311.0243 (Eyal & Sirer, "Majority is not Enough: Bitcoin Mining is Vulnerable"; CACM 2018 version). Publisher: arXiv / ACM. Accessed: 2026-09-29.

ref=[D1.9] status=unverified class=architecture pub=2017-05 — Long-range / seed-manipulation defense as a documented pattern: Algorand's look-back parameter k (40–70 rounds) exists precisely so the adversary cannot predict the next lottery seed Q by injecting fresh identities; new users are ineligible for k rounds. This is the documented "what real projects chose" answer to 51%-via-node-duplication in a lottery design: delay + seed non-manipulability, *not* a hard cap. Combined with D1.5 (VDF abandonment) and D1.8, the ordering of second-order attacks for equal-node designs is: (1) Sybil/identity duplication is the *primary* attack (it IS the 51% path — no hashrate floor to stand on), (2) long-range is more dangerous than in Bitcoin because there is no accumulated work anchoring history, (3) selfish mining is a minor tax, not an existential threat, at small network scale. Sources: https://arxiv.org/abs/1607.01341, https://eprint.iacr.org/2025/637, https://arxiv.org/abs/1311.0243. Publisher: arXiv/IACR/ACM. Accessed: 2026-09-29.

ref=[D1.10] status=unverified class=ecosystem pub=2026-09 — Namecoin (NMC) as "low-difficulty, low-hashrate" evidence: mining calculators and pool stats show NMC is a low-hashrate SHA-256 coin whose security has historically leaned on merged mining with Bitcoin; community discussion attributes the low standalone hashrate to pool behavior, not to a design goal of per-node equality. Useful as an existence proof that low-difficulty PoW chains survive, but weak on the equal-node property (odds still f(hashrate)) and the sources are calculators, not a protocol spec. Low confidence. Source: https://whattomine.com/coins/55-nmc-sha-256 (+ https://www.reddit.com/r/Namecoin/comments/31uvzo/). Publisher: WhatToMine / r/Namecoin. Accessed: 2026-09-29.

ref=[D1.11] status=unverified class=mechanism pub=2024-01 — Documented criticism of stake-weighted "democratic" lotteries: the compounding effect — "who is richer has more coins to stake, therefore a higher probability of being selected as a block validator and obtaining the corresponding rewards, thus becoming even richer" — is identified as the central stability problem of stake-weighted PoS, with a dedicated simulator paper studying it. This is the criticism that applies to Algorand-style lotteries whenever weight ≠ 1-per-node, and the reason a strict per-node re-weighting is attractive (it removes the ratchet). Source: https://www.sciencedirect.com/science/article/pii/S2096720924000356. Publisher: ScienceDirect (Blockchain: Research & Applications). Accessed: 2026-09-29.

ref=[D1.12] status=unverified class=architecture pub=2026-09 — JS simplicity + testability ranking of the families (evidence: what each design's real implementation requires):
  1. **Low-difficulty PoW with slot pacing** — simplest: validity is a single hash-vs-target comparison plus a difficulty/pace rule; no identity state, no special crypto beyond hashing; unit-testable with seeded inputs in plain JS; the hard part is economic (Sybil), not code.
  2. **VRF lottery among registered nodes** — moderate: needs a VRF/unique-signature scheme (ECDSA-style or ed25519 + hash check), seed look-back, credential verification; Algorand's full paper (BA⋆, ephemeral key stashes, 7-step protocol, k=40–70) shows how much a *provable* version costs; a minimal "one block proposer per slot via VRF + honest-majority voting" is implementable in JS but the proof machinery is the tax.
  3. **PoA hybrid (PoW + PoS vote)** — moderate: two mechanisms + reward-split bookkeeping; well documented (D1.4).
  4. **Proof-of-space / spacetime** — high: plot generation, plot grouping, compression/grinding resistance; Chia's 2026 hard fork (PoS2) shows the ongoing protocol churn and that the hard part is non-JS (disk I/O, hash-and-sort kernels, ~60k hashes/challenge).
  5. **PoCmt / human-challenge** — high/unknown: identity-bound challenges, oracle, commitment state; research-stage, no production JS reference.
  Sources: same as D1.2/D1.3/D1.4/D1.6/D1.7. Accessed: 2026-09-29.

## Synthesis for the decision

- The exact property (P ≈ f(uptime)) is achievable only if the scarce resource is **per-identity and non-parallelizable-per-identity**. Every deployed family I read (D1.2–D1.6) uses a parallelizable resource, so an operator's odds scale with N identities at near-linear cost (D1.1). Real systems' answers to multi-homing: (a) Algorand — stake-weighting + look-back delay, documents copies/keys as the multi-homing channel (D1.3, D1.9); (b) Chia — accepts linear disk-Sybil, fights *compression* instead (D1.6); (c) 2026 research (PoCmt) — makes the marginal cost of a second identity strictly linear via human-time (D1.7). No deployed system uses a **non-scaling sybil-cost deposit** (registration fee that caps odds at 1×) — that is the open design point this brief implies.
- For a JS project whose north star is "any developer can understand it": slot-paced low-difficulty PoW (D1.2, D1.12) is the easiest to implement and unit-test; a VRF lottery among registered nodes is the only family that can express "one node = one ticket" with cryptographic verification (D1.3) and is the natural second component. The realistic recommendation surface for round 2: *fixed-slot PoW (or VRF slot) + registered-identity tickets with a non-scaling entry cost*, plus explicit treatment of selfish mining (minor) and long-range anchoring (needs a PoW-like work anchor or checkpoints — D1.5 shows VDF anchors are risky).
