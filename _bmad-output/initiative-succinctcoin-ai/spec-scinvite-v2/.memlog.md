- (decision) Scope = T-B + T-C of change-ledger-dials (accepted 2026-11-04); T-D registry and T-E receipts stay RFC/spec-only, out of this contract
- (capability) WB-1 v2 envelope: scinvite:v2 one-line text = primary v1 record verbatim + backup relay candidates with signed witnesses; prefix-versioned so v1 parsers reject by prefix
- (capability) WB-2 witness issuance: any node can sign ReachabilityWitness(target identity, address, chainId, firstSeenSlot, expirySlot) with its identity key; bounded rate, declinable
- (capability) WB-3 verify floor: primary verified exactly as v1 (three gates); each backup trusted only with >=2 distinct-signer unexpired witnesses spanning a diversity floor; direct-first dial order is law
- (capability) WB-4 witness propagation: fresh witnesses ride the existing windowed announcement exchange (additive proto fields, old nodes ignore); joined nodes self-refresh backup knowledge
- (capability) WB-5 live-lease UX: panel states invites go stale when the sender sleeps, shows backup count only when non-zero, refreshes via SelfInviteUpdated; no polling timers
- (capability) WB-6 witness-grade ingest: witnessed addresses enter the address book at a grade above hints and below invite/block; never dialed before verification passes
- (constraint) Master-spec laws unchanged: primary law global v6 or held circuit; CAP-8 hop law on candidates; CAP-9 local addrs never in invites; AD-3 purity of codec/verify (slot via ctx)
- (constraint) v1 invites stay parseable and verifiable forever; v1 and v2 coexist at every surface (invite.txt, panel, boot line); T-C uses additive proto fields only, old validators accept unchanged
- (constraint) Fresh-node trust ceiling: signer chain-liveness cannot be demanded beyond the empty-chain rule (undecidable allows); k-of-n distinct signers + expiry + diversity floor are the load-bearing eclipse defenses; strict signer checks only once real blocks exist
- (constraint) Invite text keeps a hard length cap (DoS rule of MAX_INVITE_TEXT_LEN); v2 raises the cap by explicit decision only, bounded backups per bundle
- (assumption) k=2 witnesses initial floor (change doc R2), tunable constant; diversity floor = distinct /64 prefixes across v6 candidate hops
- (assumption) Messenger-first sizing (iMessage/WhatsApp effectively unbounded); SMS-friendly target preferred but not contractual
- (question) Byte budget for a v2 bundle (primary + max backups + witnesses): what hard cap replaces 4096, and how many backup candidates per invite?
- (question) Diversity metric for global /ip4 candidate hops (the /64 floor has no v4 twin): /24 per-operator heuristic or another measure?
- (question) With a chain present, must witness signers hold recent winner tickets to count toward k (strict), or only valid signatures with liveness as soft preference?
- (question) Witness expiry default in slots: reuse the 32-slot liveness lookback, or longer (relay churn is slower than ticket churn)?
- (decision) Witness expiry judged in SLOTS via verify ctx (same mechanism as the v1 validator freshness), replacing the change doc draft wall-clock TTL for T-B: no clock trust, consistent with how v1 already handles a chain-less fresh node

- (event) Self-validate pass 2 preservation PASS: E1-E4 end-state chain, R2 defenses, live-lease UX, DoS cap, verify-before-connect all landed; wrapper-only drops = method provenance, comparative matrix, morphological grid (narrative rationale stays in adopted change-doc companion)
